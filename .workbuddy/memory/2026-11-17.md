# 2026-11-17

## pg_dump 依赖体验改进

用户质疑"为什么不自带 pg_dump"。结论：pg_dump 是独立 C 客户端，且主版本必须 >= 服务端，固定内置单一版本无法覆盖多版本目标库；Docker 形态已内置 15~18。本机裸跑需要显式发现。

改动：
- `internal/config/config.go`：导出 `PgBinDirs()`，按平台探测标准路径（Windows Program Files / Linux /usr/lib / macOS Homebrew 与 Postgres.app）+ `$DATA_DIR/pgclient/*/bin` + 用户显式配置。
- `internal/pg/toolchain.go`：记录所有探测路径；`Pick` 失败时给出"探测清单 + 三种修复方式 + 版本约束原因"；新增 `Searched()`。
- `cmd/backupd/main.go`：新增 `--check-tools` 诊断模式，不连数据库即可查看发现的客户端版本与探测路径。
- `internal/pg/toolchain_test.go`：锁住错误提示要素与 zstd→gzip 回退逻辑。
- README 补充"为什么不内置 pg_dump"及探测路径说明。

验证：`go test ./...` 全绿，编译通过；用 `E:\code_repo\argus\tools\pgsql\{pgsql,pgsql17}\bin` 实测发现 15.15 与 17.8；无配置时发现 0 个并给出可操作提示。
