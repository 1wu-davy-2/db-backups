## M1 实现并端到端验证通过

- 后端 Go（chi + pgx/v5 + robfig/cron/v3 + x/crypto），前端 React 19 + Vite + TS（类型检查零错误），代码已提交 `353f492`。
- 验证结论（本地 PG17.8 + 用户 argus 工具链 pg_dump 15.15/17.8）：
  - 手动备份 5 次、cron `* * * * *` 真实触发 2 次，均 success
  - 保留策略 retain_count=3 + keep_min=2：DB 标记与对象文件同步删除，恰好剩 3 份
  - 分块 AES-GCM 加密落盘（magic "DBB1"），下载自动解密且 pg_restore --list 可解析（TOC 20 项，zstd）
  - SSE 日志（reset 事件 + 回放）、401 鉴权、审计日志均正常
- 修复的实测缺陷：GC 只标记不删对象（已补 Blob.Delete）、加密下载 Content-Length 用了密文长度（curl 18）、pg_dump 版本解析带 Debian 后缀括号、创建 target 未写 last_probe_at。
- 本机环境要点（下次会话直接用）：
  - 32 位 Go 1.24.10 编译大项目会卡死；64 位 Go 已解压在 `.local/go64/go/bin/go.exe`，用它编译
  - 本机用户是管理员组，Windows 版 PG 拒绝启动；用 `cmd //c "runas /trustlevel:0x20000 <bat>"` 绕过，但进程随会话终止，长验证必须在单条命令内完成
  - wsl.exe / schtasks.exe 在安全黑名单，Docker Desktop 崩溃后无法自动重启（需用户手动启动）
  - 本地 PG 客户端：`E:\code_repo\argus\tools\pgsql{,/pgsql17}` = 15.15/17.8；本地 PG17 数据目录 `.local/pg17data`（端口 55432，trust 认证）
